How Cluedle fits together

Cluedle is a daily 1940s-noir murder mystery on a corkboard. You read the case, catch the liar, crack a hidden cipher on paper, and name who, why, and how in five guesses. Each guess says how many of the three are right, never which. It is plain HTML, CSS, and JavaScript with no build step.

Three layers, kept apart on purpose:

  • Cases: src/cases/. Ten hand-written cases, as data. The game never generates anything.
  • Rules: src/game/. Plain functions with no screen code, all checked by npm test.
  • Screen: src/ui/ and styles/. The board, stamps, string, and cards. src/main.js wires the screen to the rules and saves progress in the browser's localStorage.

One action, start to finish: making an accusation

Reference route: three stops

A route to follow in your editor. Search for the anchor text in each file.

  1. src/ui/stamps.js, search accuseButton.addEventListener("click". The slip on the rail gathers the stamped suspect, motive, and weapon, and hands them to onAccuse. It never decides anything itself.
  2. src/main.js, search onAccuse(guess). This calls the rules, saves progress with save(), marks the spent guess, pins the next clue, and opens the ending if the case is over. It is the only place progress is saved.
  3. src/game/rules.js, search export function accuse. This counts how many of the three parts match the case's solution and returns only that count, never which. It is checked in tests/rules.test.js ("a guess never says which parts are right").

To change this, start here

  • Add or edit a case: copy a file in src/cases/, list it in src/cases/index.js (export const cases), and run npm test.
  • Rank points and bands: src/game/rank.js, const POINTS and const RANKS.
  • How forgiving the blank card is: src/game/cipher.js, export function matchesMessage.
  • The palette: styles/base.css, the variables at the top (--red, --blue, --purple). There's no orange, yellow, or green, by design.
  • A case's photo or scrawl doodle: src/ui/board.js PHOTO_SCENES, and src/ui/decoder.js DOODLES.
  • How the red string hangs and swings: src/ui/string.js, SLACK, GRAVITY, and DAMPING.

A practice to reuse

What happened. Cases 4 to 10 were drafted by seven separate AI writers from one brief. Each draft passed a per-case checker. Lined up side by side, six of the seven had chosen the same cipher key, and three had invented a suspect with the same surname. Each draft was plausible on its own; together they had converged on the same defaults.

The evidence. The review pass in devpost/checklist.md (under Revisions) fixed it by hand. The test "cipher keys are spread out across the cases" in tests/cases.test.js now guards it. It allows reuse once there are more cases than the 25 possible keys, but not piling onto one key, and not on back-to-back days. Setting case 9's key to 7 left the test green, because no other case uses 7 anymore. Copying case 8's key, 17, turned it red. A check only counts once you've seen it fail on a real duplicate.

How to use it elsewhere. When an AI produces several pieces of work, check each piece and compare the pieces against each other. Sameness is invisible one at a time. Turn whatever you catch by eye into a test, then break the data on purpose to prove the test notices.
